# spec — 소재함 (강원도 콘텐츠 소재 공유 보드) 첫 버전

## 1. 목표와 동기

강원도 공감형 콘텐츠를 캐릭터와 함께 만드는 팀이 소재를 모으고 같이 고르는 공유 보드를 만든다.
Grok(무료)이 하루 두 번(오전 8시·오후 8시 예정) X에서 강원도 관련 밈·웃긴 게시물·화제·반응을 찾아
정해진 양식으로 **관리자 Gmail(ardensdevspace@gmail.com)** 에 메일을 보낸다. Gmail에 붙은 스크립트가 그 메일을
보드로 자동 전달하고, 보드는 메일에서 소재 항목을 꺼내 카드로 보여준다. 팀원은 카드마다 저장, 삭제,
댓글, 별점을 남긴다.

메일을 거치는 이유는 **Grok을 무료로 쓰기 위해서**다. 운영도 **완전 무료**(각 서비스의 무료 요금제 안)로 한다.

사이트 이름(화면 맨 위 제목)은 **소재함**이다.

## 2. 이번 범위

**포함**
- 구글 로그인과 팀원 허용 목록. 관리자가 보드 안에서 팀원을 관리한다.
- 소재 모음, 저장됨, 휴지통 페이지. 카드별 저장, 저장 취소, 삭제, 복구를 할 수 있다.
- 댓글(작성자 본인만 수정·삭제)과 1인 1표 별점.
- 검색과 분류별 골라보기.
- 실시간 반영.
- 메일 받는 입구(API). Grok 양식에서 항목을 꺼내는 해석기, 중복 무시, 양식 오류 원문 카드.
- Gmail 자동 전달 스크립트와 설정 안내서.
- 휴지통 30일 자동 완전 삭제.

**제외 (이번에 만들지 않음)**
- 팀원이 직접 소재를 추가하는 기능
- 관리자가 메일 본문을 손으로 붙여넣는 화면. 사용자가 명시적으로 뺐고, 가져오기는 자동 전달만 한다.
- CSV 내보내기와 분석 화면. 별점·분류·반응 수 데이터는 쌓아 두지만 분석 화면은 만들지 않는다.
- X 게시물 미리보기(임베드). 카드에는 링크만 둔다.
- 알림(푸시·메일)
- 카드 내용 수정. 해석된 소재의 요약 등은 고칠 수 없다.

## 3. 사용자와 권한

- **관리자**: 1명(ardensdevspace@gmail.com). **관리자 정보는 DB 한 곳에만 둔다.** 허용 목록에 역할이 `admin`인 행으로
  있고, 이 행은 DB 마이그레이션이 처음부터 넣어 둔다. 화면은 DB 함수(예: "나는 관리자인가")로 관리자 여부를
  확인한다. 환경 변수로 따로 두지 않는다. 관리자도 팀원 기능을 모두
  쓰고, 추가로 팀원 관리 화면을 쓸 수 있다.
- **팀원**: 관리자가 허용 목록에 구글 이메일을 등록한 사람.
- **로그인**: 구글 로그인만 지원한다. 로그인한 구글 계정의 이메일(소문자로 비교)이 허용 목록에 있으면(관리자 행 포함)
  입장할 수 있다. 목록에 없으면 "등록되지 않은 계정입니다" 화면과 로그아웃 버튼만 보이고,
  어떤 데이터도 읽거나 쓸 수 없다.
- **팀원 관리** (관리자만)
  - 이메일을 추가하고 제거할 수 있다. 같은 이메일은 중복으로 등록할 수 없다.
  - 관리자는 자기 자신을 제거할 수 없다.
  - 제거된 팀원은 **즉시** 모든 데이터 읽기·쓰기가 막힌다. 다음 요청부터 막히고, 이미 열린 화면도
    다음 요청이나 실시간 갱신부터 막힌다. 그 사람이 남긴 댓글과 별점은 **이름과 함께 그대로 남는다.**
  - 제거된 이메일을 다시 추가하면, 같은 구글 계정으로 예전 댓글·별점과 이어진다.
- **제거 후 차단의 기준**: 제거 트랜잭션이 커밋된 뒤 시작하는 DB 요청은 현재 허용 목록으로 판정한다.
  JWT에 저장된 과거 팀원 여부나 브라우저 캐시를 권한 근거로 쓰지 않는다. 제거 전에 이미 받은 정보를
  회수한다는 뜻은 아니다. 실시간 연결로도 제거 후의 보드 데이터나 삭제된 행의 식별자를 보내면 안 된다.
- 열린 화면은 데이터 요청·실시간 갱신 처리 시, 재접속·탭 복귀 시 팀원 여부를 다시 확인한다. 추가로 활성 탭에서
  30초마다 확인한다. 제거를 감지하면 보드 캐시를 비우고 구독과 진행 중 요청을 정리한 뒤 입장 거부 화면을
  보여준다. 늦게 도착한 이전 요청의 응답으로 화면을 되살리지 않는다. 네트워크가 끊겼거나 브라우저가 잠든
  동안은 즉시 화면 정리를 보장하지 않으며, 복귀 시 확인을 마치기 전에는 보드를 다시 보여주지 않는다.
- **권한은 서버(DB)에서 강제한다.** 화면에서 버튼을 숨기는 것만으로는 안 된다. 팀원이 아닌 사람, 남의 댓글
  수정·삭제, 관리자가 아닌 사람의 팀원 관리는 DB 규칙으로 거부해야 한다.
  본인의 입장 가능 여부만 반환하는 판정 함수는 미등록·제거된 로그인 계정도 호출할 수 있고 `false`를 받는다.
  이 함수는 허용 목록이나 다른 사람의 정보를 반환하지 않는다.

## 4. 데이터 계약

아래 값의 **집합과 규칙**은 고정이다. 컬럼 이름과 타입의 세부는 구현이 정해도 되지만, 의미가 합쳐지거나
빠지면 안 된다.

### 4.1 회차 (메일 1통 = 회차 1개)
- `gmail_message_id` (고유). 같은 메일은 두 번 들어오지 않는다.
- `received_at`: 메일을 받은 시각. 회차 제목은 이 값을 **한국 시간(KST)** 으로 표시한다.
  예: "9/26 (금) 오후 8시". 분은 0이 아닐 때만 붙인다.

### 4.2 소재 (카드)
- `kind`: `parsed` | `raw`
  - `parsed`: 양식대로 해석된 소재
  - `raw`: 양식 오류 원문 카드. 해석하지 못한 부분의 원문을 그대로 담는다.
- `status`: `inbox` | `saved` | `trashed`
- `prev_status`: `inbox` | `saved` | 없음. 휴지통에 들어갈 때 원래 자리를 기억한다.
- `post_id`: X 게시물 번호(숫자 문자열). `parsed`만 가진다.
- `url`: 정규화한 원본 링크 `https://x.com/<계정>/status/<번호>`. `parsed`만 가진다.
- `category`: `밈` | `웃긴 게시물` | `화제` | `반응` | `기타`. `parsed`만 가진다.
- `likes`, `retweets`: 0 이상의 정수 또는 없음. Grok이 보낸 시점의 수치다.
- `summary` (요약), `reason` (재밌는 이유): 텍스트이며 비어 있을 수 있다.
- `raw_text`: `raw`만 가진다.
- `position`: 메일 안에서의 순서
- `created_at`, `saved_at` (저장한 시각), `trashed_at` (휴지통에 들어간 시각)

### 4.3 이미 본 게시물 기록
- `post_id`를 **영구히** 남기는 기록이다. 소재가 휴지통에서 완전히 삭제되어도 지우지 않는다.
- 새 메일의 항목은 `post_id`가 이 기록에 이미 있으면 **조용히 건너뛴다.** 모음·저장됨·휴지통에 있든 완전히
  삭제됐든 같다.

### 4.4 댓글
- 소재, 작성자(구글 계정), 본문(공백만 있으면 안 됨), 작성 시각, 수정 시각
- 수정된 적이 있으면 화면에 "(수정됨)"을 표시한다.

### 4.5 별점
- (소재, 사람)당 최대 1개. 점수는 정수 1~5다.
- 언제든 바꿀 수 있고 취소(삭제)할 수 있다.

### 4.6 사람 정보
- 구글 계정 기준 이메일, 표시 이름, 프로필 사진
- 허용 목록에서 제거돼도 남는다. 댓글·별점 옆에 이름을 보여주는 데 쓴다.
- 처음 로그인할 때와 이후 로그인할 때마다 DB가 자동으로 채우고 갱신한다.

### 4.7 허용 목록
- 이메일(소문자로 저장, 고유), 역할 `admin` | `member`, 추가한 날짜
- `admin` 행은 정확히 1개다(ardensdevspace@gmail.com). 마이그레이션이 넣고, 삭제하거나 역할을 바꿀 수 없다.
- 팀원 관리 화면으로는 `member` 행만 추가하거나 제거할 수 있다.

## 5. 소재 상태 규칙

| 동작 | 가능한 출발 상태 | 결과 |
|---|---|---|
| 저장 | `inbox` | `saved`. `saved_at` = 지금 |
| 저장 취소 | `saved` | `inbox`. 원래 회차 묶음으로 돌아간다. `saved_at`은 비운다 |
| 삭제 | `inbox`, `saved` | `trashed`. `prev_status` = 출발 상태, `trashed_at` = 지금 |
| 복구 | `trashed` | `prev_status`로 돌아간다. `saved`로 복구되면 기존 `saved_at`을 유지한다 |
| 완전 삭제 (자동) | `trashed`이고 `trashed_at` 후 30일 경과 | 소재와 그 댓글·별점을 영구 삭제한다. 이미 본 게시물 기록은 남긴다 |

- 모든 팀원이 저장, 저장 취소, 삭제, 복구를 할 수 있다. 수동 완전 삭제 버튼은 없다.
- **먼저 한 쪽이 반영된다.** 상태 변경은 "지금 이 출발 상태일 때만" 적용한다. 다른 팀원이 먼저 바꿔서 출발 상태가
  맞지 않으면 아무것도 바꾸지 않고 "다른 팀원이 이미 처리했어요"라고 안내한 뒤 최신 상태를 보여준다.
  예: A가 저장하는 순간 B가 삭제하면 먼저 도착한 쪽만 반영된다.
- 요청에는 사용자가 본 출발 상태 `expected_status`를 담는다. 삭제도 `inbox` 또는 `saved` 중 **그 요청이 본
  상태 하나**와 일치해야 한다. 조건 검사와 변경은 DB에서 원자적으로 실행한다. 여기서 먼저란 클라이언트의
  클릭 시각이 아니라 DB에서 조건부 변경을 먼저 성공한 쪽이다.
- `trashed` 소재에는 댓글·별점을 새로 달거나, 수정하거나, 취소할 수 없다. 기존 것은 그대로 보존하고, 복구하면
  다시 할 수 있다.
- 댓글·별점 쓰기와 휴지통 이동은 같은 소재에 대해 직렬화한다. 댓글·별점 쓰기가 먼저 완료되면 보존하고,
  휴지통 이동이 먼저 완료되면 뒤의 쓰기를 거부한다. 상태를 읽고 나중에 별도로 쓰는 방식은 허용하지 않는다.
  자동 완전 삭제와 복구도 같은 소재에서 직렬화하고 잠금 획득 후 상태·만료 조건을 다시 확인한다.
- `inbox`와 `saved` 소재에는 모두 댓글·별점을 달 수 있다. 상태가 바뀌어도 댓글·별점은 따라간다.
- 보존 기간 30일은 **조정 가능한 기본값**이다.

## 6. 화면

공통: 폰과 PC 모두에서 쓰기 좋게 반응형으로 만든다. 폰에서는 카드가 한 줄에 하나씩 놓인다. 상단에 "소재함"
제목과 페이지 이동(소재 모음 / 저장됨 / 휴지통 / 관리자에게만 보이는 팀원 관리), 로그인한 사람 정보,
로그아웃 버튼을 둔다. 모든 시각은 한국 시간으로 표시한다.

### 6.1 카드 (소재 모음과 저장됨에서 공통)
- `parsed` 카드
  - 분류 표시, 요약, 재밌는 이유, 좋아요·리트윗 수(있을 때만)
  - "원본 보기" 링크 (새 탭)
- `raw` 카드
  - "양식 오류" 표시와 원문 텍스트(줄바꿈 유지)
  - 기능은 `parsed` 카드와 같다.
- 버튼
  - 소재 모음: 저장, 삭제
  - 저장됨: 저장 취소, 삭제
  - 삭제할 때는 확인 창("휴지통으로 옮길까요?")을 띄운다.
- 별점
  - 평균(소수 첫째 자리)과 참여 인원, **누가 몇 점을 줬는지 전원의 이름·점수를 카드에 모두 표시**한다.
  - 내 별점을 1~5로 주거나 바꾸거나 취소할 수 있다.
  - 별점이 없으면 "아직 별점 없음"을 보여준다.
- 댓글
  - 목록을 오래된 순으로 보여준다. 작성자 이름, 시각, "(수정됨)" 표시를 붙인다.
  - 입력창이 있다.
  - 내 댓글에만 수정·삭제 버튼을 보여준다. 삭제할 때는 확인 창을 띄운다.

### 6.2 소재 모음 (첫 페이지)
- `inbox` 소재만 보여준다.
- **회차별로 묶는다.** 최신 회차가 위에 오고, 회차 안에서는 메일 속 순서대로 놓는다. `inbox` 소재가 하나도
  없는 회차는 제목도 표시하지 않는다.
- 저장하거나 삭제하면 카드가 이 페이지에서 **바로 빠진다.**
- 오래된 카드는 자동으로 치우지 않는다.

### 6.3 저장됨
- `saved` 소재만 보여준다.
- 기본은 **저장한 시각 최신순**이다. 전환 버튼으로 **평균 별점 높은 순**으로 바꿀 수 있다. 별점이 없는 소재는
  맨 뒤에 두고, 평균이 같으면 저장한 시각 최신순으로 놓는다.
- 저장 취소나 삭제를 하면 카드가 바로 빠진다.

### 6.4 휴지통
- `trashed` 소재를 휴지통에 들어간 시각 최신순으로 보여준다.
- 카드에는 내용, 원래 자리("소재 모음에서 삭제됨" / "저장됨에서 삭제됨"), 자동 삭제까지 남은 일수, 복구 버튼을
  둔다.
- 댓글·별점은 읽기 전용이다. 검색과 분류 골라보기는 없다.

### 6.5 검색과 분류 골라보기 (소재 모음과 저장됨)
- 검색어 입력: 대소문자를 구분하지 않는 부분 일치다. 대상은 요약, 재밌는 이유, 원문(raw), 그 소재의 댓글
  본문이다. 이 가운데 하나라도 맞으면 보여준다.
- 분류 골라보기: `전체 / 밈 / 웃긴 게시물 / 화제 / 반응 / 기타 / 양식 오류`
- 검색과 분류는 함께 적용된다. 소재 모음은 결과에서도 회차별 묶음을 유지한다.

### 6.6 팀원 관리 (관리자만)
- 허용된 이메일 목록(추가한 날짜 포함), 이메일 추가 입력, 제거 버튼(확인 창 포함)을 둔다.
- 관리자 본인 행에는 제거 버튼이 없다.
- 관리자가 아닌 사람이 이 주소로 들어오면 접근을 거부한다.

### 6.7 로그인과 입장 거부
- 로그인 화면: "Google로 로그인" 버튼 하나
- 입장 거부 화면: 3장 참고

### 6.8 실시간 반영
- 다른 팀원의 저장, 저장 취소, 삭제, 복구, 새 회차 도착, 댓글 추가·수정·삭제, 별점 변경이 **새로고침 없이** 열린
  화면에 반영된다.
- 별점 변경·취소 시 평균·인원·이름별 점수와 저장됨의 별점순 정렬을 함께 갱신한다. 댓글 추가·수정·삭제 시
  검색 결과의 포함 여부를 다시 판정한다. 현재 화면에 없는 소재도 검색 결과에 새로 나타날 수 있어야 한다.
- 페이지 공통 데이터 계층이 변경 감지와 재조회를 담당한다. 카드별 구독에만 의존하지 않는다. 변경 신호를 받으면
  현재 검색·분류·정렬 조건으로 목록과 필요한 댓글·별점을 다시 읽고, 빈 회차와 자동 완전 삭제된 카드도 정리한다.
- 최초 구독 완료 후 조회하고, 조회 중 새 변경이 오면 후속 재조회를 수행해 변경을 놓치지 않는다. 연결 복구와
  탭 복귀 시에도 권한을 확인한 뒤 재조회한다. 변경 신호는 재조회 계기이며 데이터의 정답은 DB 조회 결과다.

## 7. 메일 받는 입구 (API)

- **Supabase 서버 기능(Edge Function) `ingest`** 로 둔다. 주소는 `POST https://<프로젝트>.supabase.co/functions/v1/ingest`
  이다. 보드 사이트는 서버 없는 정적 사이트라 여기에 두지 않는다(Foundation 3장).
- Supabase 기본 로그인 토큰 검사는 끄고, 아래 비밀값으로만 인증한다.
- 인증: 헤더 `Authorization: Bearer <INGEST_SECRET>`. 비밀값이 틀리거나 없으면 `401`을 돌려주고 아무것도 쓰지
  않는다.
- 요청 본문 (JSON):
  ```json
  { "messageId": "<Gmail 메시지 ID>", "receivedAt": "<ISO 8601 시각>", "body": "<메일 본문 평문>" }
  ```
  세 값 모두 비어 있지 않은 문자열이어야 하고, `receivedAt`은 해석 가능한 시각이어야 한다. 아니면 `400`을
  돌려주고 아무것도 쓰지 않는다.
- 응답 `200` (JSON):
  ```json
  { "status": "created" | "duplicate", "batchId": "<회차 id>", "parsed": 0, "raw": 0, "skipped": 0 }
  ```
  - `created`: 새 회차를 만들었다. `parsed`와 `raw`는 새로 만든 카드 수, `skipped`는 이미 본 게시물이라 건너뛴
    수다.
  - `duplicate`: 이 `messageId`는 이미 처리했다. 아무것도 쓰지 않고 기존 회차 id를 돌려준다. 이때 세 숫자는 0이다.
- **멱등성**: 같은 `messageId`를 몇 번 보내도 회차는 1개다. 동시에 두 번 도착해도 1개다.
- **원자성**: 한 메일의 회차와 카드, 이미 본 게시물 기록은 **모두 쓰이거나 하나도 안 쓰인다.**
- 같은 `messageId`의 동시 요청은 성공한 요청이 `created`, 나머지가 기존 회차의 `duplicate`를 받는다.
  서로 다른 메일에 같은 `post_id`가 동시에 오면 카드와 이미 본 기록은 하나만 생기고 나머지는 `skipped`로 센다.
  실패로 롤백된 요청의 회차·카드·기록은 남지 않으며 재전송으로 정상 처리할 수 있다.
- 만들어진 카드가 0개면(전부 건너뜀) 회차는 기록하지만 화면에는 나타나지 않는다(6.2).

## 8. Grok 양식과 해석 규칙

### 8.1 Grok 요청 끝에 덧붙일 문장 (사용자가 확정)
```
결과는 반드시 아래 양식 그대로, 다른 말 없이 써줘. 숫자는 쉼표 없이 숫자만.
분류는 밈 / 웃긴 게시물 / 화제 / 반응 중 하나로.

===강원소재===
[1]
링크: https://x.com/.../status/...
분류: 밈
좋아요: 1234
리트윗: 56
요약: ...
재밌는 이유: ...
[2]
...
===끝===
```

### 8.2 해석 규칙
1. **블록 찾기**: 본문에서 `===강원소재===` 줄부터 다음 `===끝===` 줄(없으면 본문 끝)까지가 블록 하나다. 블록이
   여러 개면 각각 해석한다. 블록 밖의 텍스트는 무시한다.
2. **시작 표시가 없는 본문**: 본문 전체를 `raw` 카드 1장으로 만든다.
3. **항목 나누기**: 블록 안에서 `[숫자]`로 시작하는 줄마다 새 항목이 시작된다. 블록 안에 항목이 하나도 없으면
   블록 전체 텍스트를 `raw` 카드 1장으로 만든다.
4. **칸 읽기**: 항목 안에서 줄 맨 앞(앞뒤 공백 무시)이 `링크`, `분류`, `좋아요`, `리트윗`, `요약`, `재밌는 이유` 중
   하나이고 그 뒤에 콜론(`:` 또는 `：`)이 오면 그 칸의 값이 시작된다. 칸 이름으로 시작하지 않는 줄은 바로 앞 칸의
   값에 줄바꿈으로 이어 붙인다. 값은 앞뒤 공백을 제거한다.
5. **링크 → 게시물 번호**
   - 호스트가 `x.com`, `twitter.com`, 또는 그 앞에 `www.`나 `mobile.`이 붙은 형태이고 경로가
     `/<계정>/status/<숫자>`이면 유효하다.
   - `?` 뒤 쿼리, `#` 뒤 조각, 끝의 `/`, `/photo/1` 같은 추가 경로는 무시한다.
   - `post_id` = 숫자 부분, `url` = `https://x.com/<계정>/status/<숫자>`
6. **링크가 없거나 유효하지 않은 항목**: 그 항목의 원문 텍스트로 `raw` 카드를 만든다.
7. **분류**: 앞뒤 공백을 제거한 값이 `밈`, `웃긴 게시물`, `화제`, `반응` 중 하나와 정확히 같으면 그 값을 쓴다.
   그 밖의 값이나 빈 값은 `기타`로 둔다.
8. **좋아요·리트윗**: 쉼표와 공백을 제거한 뒤 숫자로만 이루어져 있으면 정수로 쓰고, 아니면 "없음"으로 둔다.
   숫자가 이상해도 카드는 만든다.
9. **중복**: `post_id`가 이미 본 게시물 기록에 있거나 같은 메일 안에서 앞서 나왔으면 건너뛰고 `skipped`에 센다.
10. **요약과 재밌는 이유가 비어 있어도** 링크가 유효하면 `parsed` 카드를 만든다.
11. `raw` 카드끼리는 중복을 검사하지 않는다. 같은 메일이 다시 들어오지 않는 것은 7장의 멱등성이 보장한다.

## 9. Gmail 자동 전달 스크립트

- 관리자 Gmail 계정에서 도는 구글 스크립트 1개다. 저장소에 코드와 설치 안내를 넣는다. 설치와 권한 승인은 사용자가
  직접 한다.
- **하루 두 번**, 한국 시간 오전 8시 10분과 오후 8시 10분 **이후**에 실행한다. Apps Script의 일일
  시간 트리거는 `nearMinute()` 기준 ±15분 오차가 있으므로 목표 시각을 각각 8:25·20:25로 설정해
  실제 시작 예상 범위를 8:10~8:40·20:10~20:40으로 둔다. 더 자주 실행하는 반복 트리거는 설치하지 않는다.
  최초 실행은 최근 **3일**(조정 가능)부터, 이후에는 **저장된 처리 완료 지점**부터
  받은 메일 중 제목의 앞뒤 공백을 제거한 값이
  **`강원도 밈 업데이트!`와 정확히 같은 메일**을 **메시지 단위**로 찾는다. 스레드로 묶여도 메시지마다 제목과
  수신 시각을 따로 확인하고 처리한다. Gmail 검색 결과는 후보이며, 최종 일치 여부는 각 메시지에서 확인한다.
- 메시지마다 `{messageId, receivedAt, body(평문)}`을 7장의 API로 보낸다.
- 최초 검색 시작 시각은 API 호출 전에 영속 저장한다. 조회 구간의 끝 시각을 고정하고 후보를 페이지 끝까지
  확인한 뒤, 대상 메시지 전부가 정상 응답을 받은 경우에만 처리 완료 지점을 그 끝 시각으로 전진시킨다.
  `200`이면서 7장의 `created`/`duplicate` 응답 형식이 유효할 때만 성공으로 본다.
- 실패·시간 초과·실행 중단 시 미완료 구간은 유지하고 다음 실행에 다시 처리한다. 스크립트가 3일 넘게 멈춰도
  완료 지점부터 따라잡는다. 검색 경계 누락 방지를 위해 완료 지점 이전 3일도 겹쳐 검색한다. 오래된 미완료
  구간을 현재 시각 기준 최근 3일로 잘라내면 안 된다. 단, Gmail에서 원본이 영구 삭제되면 복구할 수 없다.
- 이미 성공한 메시지 ID는 크기를 제한한 캐시로 기억할 수 있지만, 캐시 만료는 누락을 만들면 안 된다.
  재전송의 최종 중복 방지는 서버의 멱등성(7장)이 보장한다. 겹치는 실행은 잠금으로 막는다.
- 반복 실패한 메일도 자동으로 건너뛰지 않는다. 메시지 ID·실패 상태만 실행 로그에 남기고, 안내서에 오류 확인과
  원인 해결 후 재실행 절차를 적는다. 본문·비밀값은 로그에 남기지 않는다.
- 입구 주소(`INGEST_URL`)와 비밀값(`INGEST_SECRET`)은 스크립트 설정에 둔다. 코드에 적지 않는다.
- 메일 선별 기준은 **제목**이다. 본문의 `===강원소재===` 유무로 전달 여부를 결정하지 않는다. 제목이 일치하면
  양식을 어긴 메일도 전달하고, 시작 표시가 없으면 8.2에 따라 본문 전체를 `raw` 카드 1장으로 남긴다.
  보낸 사람 주소는 확인하지 않는다(사용자 결정: 주소를 아직 모름).

## 11. 필수 검증

- 프로젝트 검증 명령(새로 만들고 `package.json` 스크립트로 둔다)이 모두 통과해야 한다: 린트, 타입 검사,
  단위 테스트, DB 규칙 테스트, 빌드.
- **자동 테스트 범위는 "핵심 규칙만"(사용자 결정)이다.** 화면은 사람이 눌러보며 확인한다.
  - **해석기**: 8.2의 규칙 1~11을 각각 하나 이상의 테스트로 확인한다. 정상 양식, 여러 줄 요약, 전각 콜론, 링크
    변형(twitter.com, mobile., 쿼리, /photo/1), 링크 없음, 잘못된 분류, 쉼표 숫자와 이상한 숫자, 시작 표시 없음,
    끝 표시 없음, 항목 없는 블록, 같은 메일 안의 중복을 포함한다.
  - **입구 API**: 비밀값 틀림 `401`, 잘못된 본문 `400`, 같은 `messageId` 두 번 → `duplicate`에 회차 1개,
    이미 본 게시물 건너뛰기(완전 삭제된 게시물 포함)
  - **DB 규칙**:
    - 팀원 아님 → 읽기·쓰기 거부, 제거된 팀원 → 거부
    - 남의 댓글 수정·삭제 거부
    - 관리자가 아닌 사람의 팀원 추가·제거 거부, 관리자 자기 자신 제거 거부
    - 별점 범위 밖(0, 6) 거부, 1인 1표
    - 휴지통 소재에 댓글·별점 거부
    - 상태 변경은 출발 상태가 맞을 때만 적용
    - 30일 지난 휴지통 소재 삭제, 29일짜리 보존, 이미 본 게시물 기록 보존
- **동시성·롤백 자동 검증**(핵심 규칙에 포함): 독립된 DB 연결/트랜잭션으로 경합을 만들고, 순차 호출만으로
  대체하지 않는다. `pnpm verify`에 포함한다.
  - 같은 메일 동시 수신: 회차 1개, `created` 1개와 `duplicate`, 응답의 회차 ID 일치
  - 다른 메일의 동일 게시물 동시 수신: 회차는 각각 생성, 카드·이미 본 기록은 1개, 나머지는 `skipped`
  - 같은 출발 상태에서 저장·삭제 경합: 하나만 성공하고 다른 요청은 미적용. 삭제의 `expected_status` 검사 포함
  - 댓글·별점 추가·수정·삭제와 휴지통 이동 경합: 각 선후관계에서 5장의 결과 보장
  - 복구와 자동 완전 삭제 경합: 하나의 일관된 결과, 댓글·별점의 고아 행 없음
  - 메일 반영 도중 의도적으로 DB 오류 발생: 회차·카드·이미 본 기록 모두 롤백, 재전송 성공
- **권한·실시간 자동 검증**: 로컬 Supabase 클라이언트로 실제 구독을 열고 허용된 팀원의 변경 신호 수신을
  먼저 확인한 뒤 같은 토큰을 유지한 계정을 제거한다. 이후 보드 조회·쓰기·업무 RPC가 차단되고 본인 입장 판정은
  `false`를 반환한다. 변경 신호와 보드 데이터,
  댓글 삭제·별점 취소·자동 삭제의 행 ID가 전달되지 않는지 확인한다. 팀원이 아닌 계정의 신규 구독도 확인한다.
- **사람이 확인할 화면 동작**: 두 계정으로 별점 변경에 따른 재정렬, 화면 밖 소재의 댓글 변경에 따른 검색 진입·이탈,
  삭제·복구와 빈 회차 정리, 연결 복구 후 동기화를 확인한다. 팀원 제거 후 다음 권한 확인에서 입장 거부로 이동하고
  캐시가 비워지는지, 활성 탭의 30초 주기 확인 및 탭 복귀 처리도 확인한다. 화면 자동 테스트를 추가하는 요구는 아니다.
